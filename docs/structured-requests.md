# Structured requests and routing

Natural language is normalised into a reviewed `QuestionRoute` before any farm-data access. It contains intent, paddock subject, measurement key, operation, time window/label, comparison flag, presentation preference, and (when relevant) a curated education key. Deterministic routing is deliberately reserved for actions that need it: inventory, paddock identity, current retrieval, reviewed analytics, evidence, rename/confirmation, and database access.

The former router tried to turn most sentences into an operation with increasingly broad regular expressions. This proved brittle: ordinary grammar such as `sort of other information can you show me` could become a paddock candidate. The router no longer extracts arbitrary phrases after `in`, `for`, `at`, or `of`. Location extraction is allowed only after a measurement or analytic operation is already recognised; direct paddock references, aliases, and resolution remain deterministic.

Capability questions use a curated capability route. Ordinary learner language that does not request a deterministic action uses the `conversation` route, which supplies only approved learning context to Qwen; it does not perform an implied farm lookup or fall back to all moisture readings. The approved intents still include `farm_inventory_list`, `farm_inventory_count`, `paddock_summary`, current paddock measurements, `irrigation-decision`, and a short `contextual-follow-up` route.

The router accepts dynamic paddock phrases only as candidates. The canonical deterministic resolver checks active current names, audited prior names, canonical letter forms, then numeric/word-number forms. Numeric aliases use the active MariaDB paddock order: `Paddock 1` is the first active paddock, `Paddock 2` the second, and so on. This remains true after a rename, so if the original Paddock B becomes North Flat, `Paddock 2` and the audited alias `Paddock B` still resolve to North Flat's stable numeric identity. A final bounded similarity stage can resolve one clearly high-confidence name or offer `Did you mean ...?`; low-confidence input instead shows active names and a valid example. These are interpretation recoveries, not false claims that data are missing.

The API returns an opaque `conversation_id`. Web and Android send it on the next request, which allows the small 30-minute in-memory context to turn `What about Paddock 2?` into the immediately preceding supported paddock measurement or summary. It is not general chat memory and does not add any authority to Qwen.

Qwen does not choose routes, run SQL, choose a measurement, perform arithmetic, authorise a mutation, or establish a farm-specific cause or decision. It may interpret normal learner wording and give short explanations from approved learning material, but it cannot turn that material into an unverified claim about this farm.

Speech alternatives are passed to `app/speech_normalizer.py` first. It can use the active paddock names and reviewed domain vocabulary to show `Heard` versus `Interpreted`, including the documented contextual `Patek` → `paddock` correction. Typed text is not silently rewritten.
